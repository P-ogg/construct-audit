An LLM pipeline for auditing constructs

Check whether a literature’s constructs add up.

This LLM pipeline shows where measures that share a construct name behave differently, and where different names may be one construct.

Why audit constructs?

Knowledge should build on cumulative findings. When one construct name is used to describe different phenomena, findings conflict and are hard to aggregate meaningfully. When the same phenomenon is studied under different construct names, research effort is split and knowledge accumulates more slowly than it needs to.

Jingle

One construct name, different concepts

Two studies both measure “firm performance”. One uses return on assets. The other uses Tobin’s q. Pooling them might blur our understanding of firm performance instead of expanding it.

Jangle

Different construct names, one concept

Job satisfaction and organisational commitment have their own literatures. Once measurement error is removed, they can correlate close to 1 (Le et al. 2010). When two names relate to everything else in the same way, the field may be counting one finding twice.

This LLM pipeline reads articles and runs checks for construct validity. Human researchers are left to judge the results.

How it works

1

Read

Two LLM coders read each article separately and copy its correlation table. A third settles their disagreements. What it cannot settle is listed for you to check. The existence of every number found by an LLM is mechanically checked against the article by a Python script.

2

Group

Variables are grouped into constructs. You can upload your own construct codebook, otherwise an LLM will draft one.

3

Separate

How each variable was measured (a count from a database, a survey scale…) is kept apart from what it is called.

4

Check

Each kind of measure gets a profile: its correlations with common constructs. Profiles are compared with each other and with random splits.

This LLM pipeline requires an API key to run. It runs on proprietary models (e.g. Claude) or on open models (through OpenRouter, Groq, or your own computer). Your API key stays in your browser session and is never stored.

Audit your literature

Upload PDFs, choose a model, add an API key, and get the report. Up to 100 articles here; each takes a few minutes, so a large set takes a few hours (you can save your progress and resume). Larger sets need to be run from the command line. Already coded your studies? Upload them with the Excel template in the app; no API key is needed. If nobody has used the app for a while, it may take a minute to wake up. Open in a new tab.

Findings are evidence for human researchers to judge, not verdicts.
